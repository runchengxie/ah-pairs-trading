# 数据、FX 与缓存

## 数据输入优先级

项目支持两种主要数据入口：

- 显式传本地 CSV
- 在线拉取 A/H 历史并自动缓存

优先级规则如下：

- 如果显式传了 `--a-csv` / `--h-csv` / `--fx-csv`，程序会直接使用这些文件
- 如果没有显式传 A/H CSV，程序会先查本地缓存
- 本地没有缓存时，才会通过 AkShare 在线拉取 A/H 历史

FX 不会自动联网拉取，必须自己提供：

- `--fx-csv`
- 或 `--constant-fx-rate`

## A/H 与 FX 的价格口径

项目最终研究的不是原始 H 股港币价格，而是人民币口径下的 H 股价格：

```text
h_close_cny = h_close_hkd * fx_rate * share_ratio
```

其中：

- `fx_rate` 是 HKD/CNY
- `share_ratio` 用于处理 A/H 股数换算关系，默认是 `1.0`

这一步是 A/H 相对价值研究的基础，不是可有可无的装饰项。

## 日期对齐

项目会对齐 A 股、H 股和 FX 历史，并在共同可研究日期上构建价格序列。

当前实现的重点是：

- A/H 历史各自先标准化
- 再按共同日期做对齐
- FX 在对齐后按日期前向填充

## `--constant-fx-rate` 与 `--fx-csv`

### `--constant-fx-rate`

适合：

- smoke test
- 快速原型验证
- 环境检查

不适合：

- 正式回测
- 严肃研究
- 长样本的结果解释

### `--fx-csv`

更适合：

- 正式回测
- 复现实验
- 需要保留历史汇率波动影响的研究

## Same-Issuer 校验

项目内置了一份人工维护的 A/H same-issuer registry，用于拦截明显错配。

默认行为：

- `--same-issuer-check strict`

这会拦住已知错配，例如：

- `601857/00883`

该组合会被识别为：

- `601857` 对应 PetroChina
- `00883` 对应 CNOOC

可选行为：

- `warn`
- `off`

如果你要故意做跨公司配对研究，可以手动放宽。

## 数据缓存与阶段缓存

这里有两类不同缓存：

- 数据缓存：A/H 历史行情缓存，默认会自动参与
- 阶段缓存：pipeline 中间计算结果缓存，只有显式加 `--resume-from-cache` 才会恢复

`--resume-from-cache` 的作用是：

- 复用已经完成的 pipeline 阶段

它做不到：

- 跳过训练集协整显著性校验
- 改写数据源优先级
- 把不存在的本地 CSV 自动变成在线拉取

## 本地 CSV 的使用建议

显式传本地 CSV 适合：

- 离线研究
- 使用自己清洗过的数据
- 固定输入以便复现实验

注意：

- 路径不存在时会立刻报错
- 仓库不附带示例 CSV
- 需要把占位路径替换成你机器上的真实文件
